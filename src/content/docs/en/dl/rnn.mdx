## Intuition

### Ordered data

Read two short sentences: "dog bites man" and "man bites dog." The exact same three words, yet the meaning is reversed. Or look at hourly temperature readings: 24, 25, 27, 29... To predict the next hour, you need to know the order the numbers arrived in, not just which numbers appeared.

Text, time series, audio, and DNA strands are all **sequential data**: a sequence $\mathbf{x}_1, \mathbf{x}_2, \dots, \mathbf{x}_L$ where order carries meaning and the length $L$ varies from sample to sample. A product review might be 5 words long or 500 words long.

### Why an MLP does not fit

The MLP from [Artificial Neural Networks](/en/dl/neural-networks/) takes a fixed-size vector. There are two ways to force a sequence into that mold, and both run into trouble:

- **Concatenate all steps into one long vector.** You must pick a maximum length in advance, pad shorter sequences with zeros, and truncate longer ones. Worse, every position gets its own separate weights. Learning that the word *great* at position 2 is praise does nothing for the word *great* at position 7: the network has to relearn it from scratch at every position.
- **Sum or average all steps.** Now the dimension is fixed, but order is completely lost. "Dog bites man" and "man bites dog" collapse into the exact same vector.

### Reading word by word and keeping a note

You do not read this sentence by taking in the whole line at once. You read word by word, keeping a running "summary" in your head of what you have read so far. Each time you meet a new word, you update that summary. And your updating skill is the same at every word: you do not use one reading skill for the 3rd word and a different skill for the 30th.

An RNN works the exact same way. It maintains a vector called the hidden state. At each step, it takes the previous state and the new input, runs them through **the same formula with the same set of weights**, and produces the new state. Because of that, it can read sequences of any length, and whatever it learns at one position automatically applies at every other position.

The problem for this lesson is: **build a network that reads a sequence of arbitrary length in order, remembers what it has read inside a state vector, and can be trained end to end; then understand why it still struggles to remember things from many steps ago.**

## Theory

### Hidden state and the one-step formula

At step $t$ (from $1$ to $L$), an RNN receives the input $\mathbf{x}_t \in \mathbb{R}^{d_x}$ and the previous hidden state $\mathbf{h}_{t-1} \in \mathbb{R}^{d_h}$, then computes the new state:

$$
\mathbf{h}_t = \tanh\left(\mathbf{W}_{xh} \mathbf{x}_t + \mathbf{W}_{hh} \mathbf{h}_{t-1} + \mathbf{b}_h\right)
$$

- $d_x$ is the input dimension, and $d_h$ is the hidden state dimension (a hyperparameter, such as 32 or 256).
- $\mathbf{W}_{xh} \in \mathbb{R}^{d_h \times d_x}$ maps the new input into the state space.
- $\mathbf{W}_{hh} \in \mathbb{R}^{d_h \times d_h}$ is the **recurrent weight** matrix: it governs how the old state shapes the new state. This is the "recurrent" part of the name.
- $\mathbf{b}_h \in \mathbb{R}^{d_h}$ is the bias vector.
- $\tanh$ squashes each component into $(-1, 1)$, keeping the state from blowing up even across hundreds of steps.
- The initial state $\mathbf{h}_0$ is usually set to the zero vector.

The matrix subscript notation reads like an arrow: the first letter is what gets multiplied, and the second letter is what gets produced. $\mathbf{W}_{xh}$ goes from $\mathbf{x}$ to $\mathbf{h}$, while $\mathbf{W}_{hh}$ goes from the old $\mathbf{h}$ to the new $\mathbf{h}$. The [GRU](/en/dl/gru/) and [LSTM and BiLSTM](/en/dl/lstm-bilstm/) lessons keep this exact convention, replacing the second letter with the gate name (such as $\mathbf{W}_{xf}, \mathbf{W}_{hf}$ for the forget gate).

Whenever we need a prediction at step $t$, we pass $\mathbf{h}_t$ through a linear output layer:

$$
\hat{\mathbf{y}}_t = \mathbf{W}_{hy} \mathbf{h}_t + \mathbf{b}_y
$$

For classification, $\hat{\mathbf{y}}_t$ holds the logits, and we apply softmax just like at the output of an MLP. For regression—such as predicting the next value of a numerical series—$\hat{\mathbf{y}}_t$ is the prediction directly.

Notice the chain of dependencies: $\mathbf{h}_t$ depends on $\mathbf{h}_{t-1}$, which depends on $\mathbf{h}_{t-2}$, all the way back to $\mathbf{x}_1$. Thus $\mathbf{h}_t$ is a summary of **the entire prefix** $\mathbf{x}_1, \dots, \mathbf{x}_t$, compressed into $d_h$ numbers. It depends only on past and present steps, never seeing future steps.

### Unrolling through time and weight sharing

The recurrence above has a loop: the output $\mathbf{h}_t$ feeds back in as an input at the next step. To compute activations and take derivatives, we **unroll** the network through time: we draw one copy of the RNN cell for each step and connect $\mathbf{h}_1 \to \mathbf{h}_2 \to \dots \to \mathbf{h}_L$.

$$
\mathbf{h}_0 \xrightarrow{\ \mathbf{x}_1\ } \mathbf{h}_1 \xrightarrow{\ \mathbf{x}_2\ } \mathbf{h}_2 \to \cdots \xrightarrow{\ \mathbf{x}_L\ } \mathbf{h}_L
$$

Once unrolled, an RNN looks like a feedforward network of $L$ layers. The crucial difference is **weight sharing**: **every "layer" uses the exact same $\mathbf{W}_{hh}$, $\mathbf{W}_{xh}$, and $\mathbf{b}_h$**. This has three consequences:

1. **The parameter count does not depend on $L$.** An RNN layer has $d_h^2 + d_h d_x + d_h$ parameters whether the sequence is 10 steps long or 10,000 steps long.
2. **Learn once, use everywhere.** A rule like "seeing the word *great* nudges the state toward positive sentiment" lives inside $\mathbf{W}_{xh}$ and applies at any step.
3. **Generalize to sequences longer than any seen during training.** You simply run the step formula for more steps.

You will see the rolled RNN cell alongside its unrolled graph in the Illustration section.

### Sequence task patterns

Using the same RNN backbone, different choices of where we feed inputs and where we read outputs give four common patterns:

| Pattern | Input | Output | Example |
|---|---|---|---|
| One-to-many | A single vector (often used as $\mathbf{h}_0$ or $\mathbf{x}_1$) | $\hat{\mathbf{y}}_1, \dots, \hat{\mathbf{y}}_L$ | Image captioning |
| Many-to-one | $\mathbf{x}_1, \dots, \mathbf{x}_L$ | Only $\hat{\mathbf{y}}_L$, computed from $\mathbf{h}_L$ | Sentiment classification of a review |
| Many-to-many (aligned) | $\mathbf{x}_1, \dots, \mathbf{x}_L$ | $\hat{\mathbf{y}}_t$ at every step | Part-of-speech tagging; next-step prediction |
| Many-to-many (unaligned) | Source sequence | Target sequence of a different length | Machine translation |

The last pattern requires two RNNs: an encoder that reads the source sentence and a decoder that generates the target sentence. That is the topic of [Sequence-to-Sequence Models (Seq2Seq)](/en/llm/seq2seq/).

For aligned many-to-many tasks, the total loss is the sum of the per-step losses, $\mathcal{L} = \sum_{t=1}^{L} \mathcal{L}_t$, where $\mathcal{L}_t$ compares $\hat{\mathbf{y}}_t$ against the target at step $t$. For many-to-one tasks, there is only $\mathcal{L}_L$. In code, we usually average instead of summing; that simply scales the gradient by a constant.

### Backpropagation through time (BPTT)

To train the network, we need the gradients of $\mathcal{L}$ with respect to $\mathbf{W}_{hh}$, $\mathbf{W}_{xh}$, and $\mathbf{b}_h$. Once unrolled, the RNN is an $L$-layer feedforward network, so we apply standard backpropagation from [Training Neural Networks](/en/dl/training-neural-networks/), working backward from step $L$ down to step $1$. This procedure is called **backpropagation through time** (BPTT). Two things are new compared to a standard MLP: $\mathbf{h}_t$ affects the loss along two paths, and the weights are reused at every step.

For brevity, write $\boldsymbol{\delta}_t = \partial \mathcal{L} / \partial \mathbf{h}_t$ for the gradient of the total loss with respect to the hidden state at step $t$, a vector of the same shape as $\mathbf{h}_t$.

**Step 1: gradient with respect to hidden states.** $\mathbf{h}_t$ influences the total loss through two routes: directly through $\mathcal{L}_t$ (via $\hat{\mathbf{y}}_t$), and indirectly through $\mathbf{h}_{t+1}$ and all subsequent steps. The multivariable chain rule adds the two contributions:

$$
\boldsymbol{\delta}_t = \frac{\partial \mathcal{L}_t}{\partial \mathbf{h}_t} + \left(\frac{\partial \mathbf{h}_{t+1}}{\partial \mathbf{h}_t}\right)^{\!\top} \boldsymbol{\delta}_{t+1}
$$

At the final step there is no $\mathbf{h}_{L+1}$, so $\boldsymbol{\delta}_L = \partial \mathcal{L}_L / \partial \mathbf{h}_L$. From there we step backward to compute $\boldsymbol{\delta}_{L-1}, \boldsymbol{\delta}_{L-2}, \dots, \boldsymbol{\delta}_1$.

**Step 2: the one-step Jacobian.** The factor $\partial \mathbf{h}_{t+1} / \partial \mathbf{h}_t$ is a $d_h \times d_h$ **Jacobian matrix**: its $(i, j)$ entry is the derivative of component $i$ of $\mathbf{h}_{t+1}$ with respect to component $j$ of $\mathbf{h}_t$. Since $\mathbf{h}_{t+1} = \tanh(\mathbf{W}_{hh} \mathbf{h}_t + \dots)$ and $\tanh'(u) = 1 - \tanh^2(u)$ acts elementwise, the chain rule gives:

$$
\frac{\partial \mathbf{h}_{t+1}}{\partial \mathbf{h}_t} = \mathbf{D}_{t+1} \mathbf{W}_{hh}, \qquad
\mathbf{D}_{t+1} = \mathrm{diag}\left(\mathbf{1} - \mathbf{h}_{t+1} \odot \mathbf{h}_{t+1}\right)
$$

$\mathbf{D}_{t+1}$ is the diagonal matrix of elementwise $\tanh$ derivatives, computed directly from the $\mathbf{h}_{t+1}$ saved during the forward pass. Every diagonal entry lies in $(0, 1]$.

**Step 3: gradients with respect to weights.** At step $t$, $\mathbf{W}_{hh}$ multiplies $\mathbf{h}_{t-1}$, just like a linear layer taking input $\mathbf{h}_{t-1}$. The gradient with respect to the pre-activation of $\tanh$ at step $t$ (multiplying $\boldsymbol{\delta}_t$ by the $\tanh$ derivative, as in Step 2) is $\mathbf{D}_t \boldsymbol{\delta}_t$, so step $t$ contributes the outer product $(\mathbf{D}_t \boldsymbol{\delta}_t)\, \mathbf{h}_{t-1}^\top$, just like a linear layer in an MLP. Because $\mathbf{W}_{hh}$ is shared across **all** steps, its total gradient is the sum of those per-step contributions:

$$
\begin{aligned}
\frac{\partial \mathcal{L}}{\partial \mathbf{W}_{hh}} &= \sum_{t=1}^{L} (\mathbf{D}_t \boldsymbol{\delta}_t)\, \mathbf{h}_{t-1}^\top \\
\frac{\partial \mathcal{L}}{\partial \mathbf{W}_{xh}} &= \sum_{t=1}^{L} (\mathbf{D}_t \boldsymbol{\delta}_t)\, \mathbf{x}_t^\top \\
\frac{\partial \mathcal{L}}{\partial \mathbf{b}_h} &= \sum_{t=1}^{L} \mathbf{D}_t \boldsymbol{\delta}_t
\end{aligned}
$$

Summing across time steps is the only extra rule introduced by weight sharing. The gradients for $\mathbf{W}_{hy}$ and $\mathbf{b}_y$ work just like an MLP output layer, also summed over steps that produce a loss.

:::note[Key takeaway]
BPTT is standard backpropagation on the unrolled network. Hidden-state gradients flow backward via $\boldsymbol{\delta}_t = \partial \mathcal{L}_t / \partial \mathbf{h}_t + (\mathbf{D}_{t+1} \mathbf{W}_{hh})^\top \boldsymbol{\delta}_{t+1}$. Weight gradients sum the contributions of every step because all steps share the same weights. Because BPTT must store every $\mathbf{h}_t$ from the forward pass, memory grows linearly with $L$.
:::

### Why RNNs struggle with long-range memory

Suppose the label at step $L$ depends on an input at a much earlier step $t$. To learn that relationship, the gradient from $\mathcal{L}_L$ must travel all the way back to $\mathbf{h}_t$. Unrolling the recursion from Step 1, the contribution flowing from $\mathbf{h}_L$ back to $\mathbf{h}_t$ is:

$$
\frac{\partial \mathcal{L}_L}{\partial \mathbf{h}_t} = \left(\frac{\partial \mathbf{h}_L}{\partial \mathbf{h}_t}\right)^{\!\top} \frac{\partial \mathcal{L}_L}{\partial \mathbf{h}_L}, \qquad
\frac{\partial \mathbf{h}_L}{\partial \mathbf{h}_t} = \mathbf{D}_L \mathbf{W}_{hh}\, \mathbf{D}_{L-1} \mathbf{W}_{hh} \cdots \mathbf{D}_{t+1} \mathbf{W}_{hh}
$$

The right-hand side is the product of $L - t$ one-step Jacobians, each equal to $\mathbf{D}_k \mathbf{W}_{hh}$. Unlike a deep MLP where each layer has its own weight matrix, here **the exact same matrix $\mathbf{W}_{hh}$ is multiplied repeatedly** $L - t$ times.

**The 1D case.** Suppose $d_h = 1$ and the state stays near 0 so $\tanh' \approx 1$. Each Jacobian is just the scalar $w$, and $\partial h_L / \partial h_t \approx w^{L-t}$. Over a distance of $L - t = 50$: if $w = 0.9$, then $0.9^{50} \approx 0.005$; if $w = 1.1$, then $1.1^{50} \approx 117$. A $\pm 0.1$ nudge around $1$ changes the result by more than a factor of twenty thousand.

**The general case.** Using submultiplicativity of the spectral norm $\lVert \mathbf{A}\mathbf{B} \rVert \le \lVert \mathbf{A} \rVert \lVert \mathbf{B} \rVert$, where $\lVert \cdot \rVert$ is the largest **singular value** $\sigma_{\max}$ (the maximum factor by which a matrix can stretch any vector), and noting that each diagonal matrix $\mathbf{D}_k$ has entries in $(0, 1]$ so $\lVert \mathbf{D}_k \rVert \le 1$, we obtain:

$$
\left\lVert \frac{\partial \mathbf{h}_L}{\partial \mathbf{h}_t} \right\rVert
\le \prod_{k=t+1}^{L} \lVert \mathbf{D}_k \rVert \, \lVert \mathbf{W}_{hh} \rVert
\le \sigma_{\max}(\mathbf{W}_{hh})^{\,L-t}
$$

- **Vanishing gradient.** If $\sigma_{\max}(\mathbf{W}_{hh}) < 1$, the upper bound shrinks to 0 exponentially in the distance $L - t$. This is a **sufficient** condition: gradients are guaranteed to vanish. Saturation of $\tanh$ (states near $\pm 1$, where the derivative is near 0) makes them shrink even faster.
- **Exploding gradient.** For the product to grow with distance, $\sigma_{\max}(\mathbf{W}_{hh}) > 1$ is a **necessary** condition, though not sufficient because the $\mathbf{D}_k$ matrices can still pull the product down. When explosion happens, a few updates with huge gradients hurl the weights far away, causing the loss to spike or turn into NaN.

Pascanu, Mikolov, and Bengio (2013) proved both conditions (for $\tanh$; with sigmoid activations, the threshold is 4 instead of 1 because the sigmoid derivative is at most $1/4$). Earlier, Bengio, Simard, and Frasconi (1994) showed that the longer a dependency spans, the harder it is for gradient descent to learn. The practical effect is clear from the BPTT sum: the gradient with respect to $\mathbf{W}_{hh}$ adds terms from all distances, and long-range terms are exponentially smaller than short-range terms. Short-range signals dominate the update, so the network mainly learns relationships between nearby steps.

We already met vanishing gradients in deep MLPs in [Training Neural Networks](/en/dl/training-neural-networks/). In an RNN, "depth" is sequence length, and a sentence or sensor stream easily spans hundreds of steps.

### Truncated BPTT

Running full BPTT on a very long sequence (an entire book, or a year of hourly measurements) both consumes huge memory—since every $\mathbf{h}_t$ must be stored—and updates the weights only once at the very end. **Truncated BPTT** splits the sequence into consecutive chunks of length $K$:

1. Run the forward pass on the first chunk starting from $\mathbf{h}_0$, compute the chunk loss, backpropagate **only within that chunk**, and update the weights.
2. Carry the final hidden state of the chunk over as the initial state of the next chunk, but **detach its gradient history**—treating it as a constant vector.
3. Repeat until the end of the sequence.

The forward pass remains continuous, so $\mathbf{h}$ can still carry information from earlier chunks. In exchange, gradients never travel farther than $K$ steps, so the network is not directly trained to hold onto information across more than $K$ steps. Memory scales with $K$ rather than $L$. In PyTorch, step 2 is `h = h.detach()`, as shown in the third code cell.

### Gradient clipping

For exploding gradients, the simplest remedy is **gradient norm clipping**. Let $\mathbf{g}$ be the vector formed by concatenating all parameter gradients of the model, and let $\tau$ be a chosen threshold. Before each optimizer step:

$$
\text{if } \lVert \mathbf{g} \rVert > \tau \text{ then } \mathbf{g} \leftarrow \frac{\tau}{\lVert \mathbf{g} \rVert}\, \mathbf{g}
$$

The rescaled vector has norm exactly $\tau$ while keeping its original direction. The gradient still points downhill, only with a capped step size, so a single bad batch cannot fling the weights off course. Pascanu et al. suggest picking $\tau$ by observing the average gradient norm over many updates; in their experiments, thresholds between half and ten times that average worked well. In PyTorch, this is `torch.nn.utils.clip_grad_norm_`.

Clipping only shrinks gradients that are too large. It **never** enlarges gradients that have vanished, so it does not help an RNN remember farther back.

### Limitations

- **Hard to remember far back.** Vanishing gradients restrict vanilla RNNs to mostly local context. Truncated BPTT and gradient clipping stabilize training, but they do not fix this fundamental decay. The second code cell lets you measure how fast the gradient shrinks.
- **Inherently sequential.** Computing $\mathbf{h}_t$ requires $\mathbf{h}_{t-1}$, preventing parallelization across time steps. [Transformers](/en/dl/transformers/) remove this recurrence entirely.
- **Everything is squeezed into one vector.** The entire history must pass through a $d_h$-dimensional vector $\mathbf{h}_t$. [Sequence-to-Sequence Models (Seq2Seq)](/en/llm/seq2seq/) shows why this becomes a bottleneck when translating long sentences.

- **$c = 0.5$: vanishing.** At distance 10 the norm is $9.5 \times 10^{-4}$, right below the upper bound $0.5^{10} \approx 9.8 \times 10^{-4}$ because the states are small and $\mathbf{D}_k$ is close to the identity matrix. By distance 40 it is down to $7.1 \times 10^{-13}$: an input 40 steps earlier sends virtually zero signal to the weights.
- **$c = 1.0$: slow decay.** The upper bound is 1, yet $\tanh' < 1$ still whittles the norm down gradually: 0.73 at distance 10, and 0.14 at distance 40. This is the regime where a vanilla RNN learns best, and it is a very narrow ridge.
- **$c = 2.0$: exploding.** The norm grows from 1.9 at distance 1 to $3.2 \times 10^{1}$ at distance 10 and $6.7 \times 10^{3}$ at distance 40. That is still far below the upper bound $2^{40} \approx 10^{12}$ because the states grow large and $\tanh$ saturation dampens the product. As noted in the Theory section, $\sigma_{\max} > 1$ is necessary for explosion, not sufficient.

Try changing `c` to 0.9 or 1.1, or increasing the `0.1` multiplier on `xs` to 1.0, and re-run the cell to see how $\tanh$ saturation accelerates gradient decay.

### PyTorch RNN predicting the next value of a sine wave

The script below trains `nn.RNN` on an aligned many-to-many task: at every step, it reads the current value of a noisy sine wave and predicts the next value.

- **Synthetic data:** $\sin(0.1\,t)$ plus Gaussian noise of standard deviation 0.05, over 2,000 steps. The input is $x_t$ and the target is $x_{t+1}$.
- **Model:** `nn.RNN(1, 32)` ($d_x = 1$, $d_h = 32$, $\tanh$ activation) followed by `nn.Linear(32, 1)` for $\hat{y}_t = \mathbf{W}_{hy} \mathbf{h}_t + b_y$. PyTorch computes $\mathbf{h}_t$ with two bias vectors, `bias_ih` and `bias_hh`, whose sum plays the role of $\mathbf{b}_h$ in our formula.
- **Truncated BPTT:** the 2,000-step series is split into 40 chunks of length $K = 50$. The final state of each chunk is passed to the next via `h.detach()`.
- **Gradient clipping** with threshold $\tau = 1$. `clip_grad_norm_` returns the gradient norm **before** clipping; the script logs the maximum pre-clip norm seen in each epoch.
- **Training:** 15 epochs with Adam (600 parameter updates in total). We then evaluate on a fresh 500-step segment and compare against the simplest baseline: predicting that the next value equals the current value.

## Common pitfalls

:::caution[Thinking each time step has its own weights]
Because the unrolled diagram looks like $L$ layers, it is tempting to think an RNN has $L$ sets of weights and that its parameter count grows with sequence length. It does not: every step shares $\mathbf{W}_{hh}$, $\mathbf{W}_{xh}$, and $\mathbf{b}_h$, just as the first NumPy cell has 22 parameters whether it reads 2 steps or 4. The backpropagation corollary: per-step weight gradients are **summed** into the same matrix rather than updating separate matrices at each step.
:::

:::caution[Forgetting to detach the hidden state between truncated BPTT chunks]
In truncated BPTT, if you remove `h = h.detach()` in the PyTorch script, `h` from the previous chunk stays connected to the old computation graph. The second call to `backward()` then tries to backpropagate into the previous chunk's graph—which PyTorch has already freed—raising a `RuntimeError` with "Trying to backward through the graph a second time." Passing `backward(retain_graph=True)` as suggested by the error message is the wrong fix: it forces gradients all the way back to the start of the sequence, defeating truncated BPTT, and in this loop it immediately triggers another error ("modified by an inplace operation") because the old graph depends on weights that `opt.step()` has already overwritten. Conversely, resetting `h = None` at each chunk avoids the error but wipes out the context from earlier chunks.
:::

:::caution[Believing gradient clipping fixes vanishing gradients]
Clipping only scales down gradient vectors whose norm exceeds the threshold. When a gradient from 40 steps back has already shrunk to $10^{-13}$ (second code cell, $c = 0.5$), clipping leaves it untouched. Clipping prevents explosion; remembering over long distances requires gated architectures like GRUs and LSTMs.
:::

:::caution[Mixing up tensor axis order in PyTorch]
By default, `nn.RNN` expects inputs shaped `(seq_len, batch_size, d_x)`, not `(batch_size, seq_len, d_x)`. If your data has the batch on the first axis and you forget `batch_first=True`, PyTorch will not raise a shape error because the last axis is still $d_x$: instead, it treats each sample in the batch as a time step and reads "across" different samples. The code runs and prints a decreasing loss, making the bug silent. Always check `x.shape` right before calling the model.
:::

## Summary and further reading

**Key takeaways:**

- An RNN reads a sequence step by step and updates a hidden state $\mathbf{h}_t = \tanh(\mathbf{W}_{xh} \mathbf{x}_t + \mathbf{W}_{hh} \mathbf{h}_{t-1} + \mathbf{b}_h)$ that summarizes all steps seen so far; the prediction at step $t$ is $\hat{\mathbf{y}}_t = \mathbf{W}_{hy} \mathbf{h}_t + \mathbf{b}_y$.
- Unrolled through time, an RNN is an $L$-layer deep network with shared weights: its parameter count is independent of $L$, it handles variable-length sequences, and it is sensitive to order. Depending on where outputs are read, we get one-to-many, many-to-one, and many-to-many patterns.
- BPTT is backpropagation on the unrolled graph; weight gradients sum the contributions of all steps. The gradient from step $L$ back to step $t$ multiplies $L - t$ Jacobians $\mathbf{D}_k \mathbf{W}_{hh}$, shrinking or growing exponentially with distance: $\sigma_{\max}(\mathbf{W}_{hh}) < 1$ guarantees vanishing gradients, while $\sigma_{\max}(\mathbf{W}_{hh}) > 1$ is necessary for exploding gradients.
- Truncated BPTT restricts backpropagation to $K$-step chunks to save memory; gradient clipping rescales overly large gradients to norm $\tau$. Both stabilize training, but neither solves long-range memory.

The natural next question is: how can we let gradients travel across hundreds of steps without vanishing? The [GRU](/en/dl/gru/) lesson answers this with **gates**: instead of overwriting the hidden state with $\tanh(\dots)$ at every step, the network learns how much of the old state to keep, creating a nearly direct highway for both information and gradients.
