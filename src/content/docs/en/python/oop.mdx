## Intuition

Imagine building a computer vision system with a 50-layer neural network:
- Each layer holds thousands of weight parameters $\mathbf{W}$ and biases $\mathbf{b}$.
- Each layer needs to cache intermediate activations during the forward pass to compute gradients during backpropagation.
- If you only used standalone functions and loose dictionaries (`dict`), you would have to pass dozens of parameter dictionaries back and forth between functions. A single typo in a dictionary key would silently break your entire network.

**Object-Oriented Programming (OOP)** solves this problem cleanly. It lets you treat each neural network layer as a **self-contained machine**:
- Each machine stores its own weights safely inside its housing (**Encapsulation**).
- New machines can be built on top of an existing standard blueprint without starting from scratch (**Inheritance**).
- Every machine exposes the exact same "Predict" button on the outside, whether its interior is a convolutional layer or a Transformer block (**Polymorphism**).

## Theory

### Classes, Objects, and `self`

- **Class:** A blueprint or template that defines what attributes an entity has and what operations it can perform.
- **Object (Instance):** A concrete entity created in memory from a class blueprint.
- **`__init__`:** A special initializer method that Python calls automatically whenever a new object instance is created.
- **`self`:** The first parameter of every instance method, referring to the specific object instance on which the method is called.

```python
class Neuron:
    def __init__(self, weight: float, bias: float):
        # Instance attributes
        self.w = weight
        self.b = bias

    def activate(self, x: float) -> float:
        # Instance method
        return self.w * x + self.b
```

### Class Attributes vs. Instance Attributes

One of the most common pitfalls in Python AI programming is confusing two kinds of attributes:

1. **Instance Attributes:** Assigned via `self.attribute_name` inside methods (typically `__init__`). Every object instance gets its own independent copy in memory.
2. **Class Attributes:** Defined directly inside the `class` body, outside of any method. Every instance of the class shares the exact same memory reference. If a class attribute holds a mutable object (such as a `list` or `dict`), mutating it on one instance silently mutates it across all other instances!

### The Four Pillars of OOP in AI

#### 1. Encapsulation

Encapsulation bundles data (attributes) and the methods that operate on that data into a single unit while restricting direct external tampering.

In Python, encapsulation relies on naming conventions with leading underscores:
- `_attribute`: Protected convention—signals that the attribute is internal and should not be accessed directly from outside the class.
- `__attribute`: Triggers name mangling to prevent accidental name collisions in subclasses.

#### 2. Inheritance

Inheritance lets a new class (**child class** or subclass) inherit all attributes and methods from an existing class (**parent class** or superclass), while adding new features or overriding specific methods.

In PyTorch, every neural network model inherits from `torch.nn.Module`:

```python
# Subclass inheriting from parent class nn.Module
class MyClassifier(nn.Module):
    def __init__(self, in_features: int, out_features: int):
        super().__init__()  # Initialize nn.Module internals
        self.linear = nn.Linear(in_features, out_features)

    def forward(self, x):
        return self.linear(x)
```

Calling `super().__init__()` sets up `nn.Module`'s internal machinery so the model automatically tracks gradients, moves parameters between CPU and GPU, and exports checkpoints.

#### 3. Polymorphism

Polymorphism is the ability of different object types to respond in their own way to the same method call.

The Scikit-Learn ecosystem is a textbook example of polymorphism:
- Every estimator—from `LinearRegression` and `DecisionTreeClassifier` to `RandomForestRegressor`—implements two standard methods:
  - `model.fit(X, y)`: Train the model to find optimal parameters.
  - `model.predict(X)`: Run inference to produce predictions.
- Thanks to polymorphism, you can write a single evaluation pipeline that accepts any estimator object without changing a single line of evaluation code.

#### 4. Abstraction

Abstraction hides complex internal implementation details and exposes only a clean, minimal interface to the outside world.

Python supports formal abstraction through the standard `abc` (Abstract Base Classes) module. An abstract base class marks required methods with the `@abstractmethod` decorator, forcing every concrete subclass to implement them before it can be instantiated.

### Magic Methods (Dunder Methods)

Python provides special methods surrounded by double underscores (**dunder methods**) that let your custom objects integrate seamlessly with built-in Python syntax:

- `__len__(self)`: Enables calling `len(obj)`—commonly used to return the number of samples or batches in a dataset.
- `__getitem__(self, idx)`: Enables indexing syntax `obj[idx]`.
- `__call__(self, *args)`: Makes an object callable like a function: `obj(x)`. This is how PyTorch lets you write `output = model(input)` instead of explicitly calling `model.forward(input)`.

## Common pitfalls

:::caution[Using mutable class attributes instead of instance attributes]
If you declare `class Model: layers = []`, that single `layers` list is shared across every instance of `Model`. When one model appends a layer, every other model instance sees it too! Always initialize mutable attributes inside `def __init__(self): self.layers = []`.
:::

:::caution[Forgetting `self` as the first parameter of a method]
Every instance method definition inside a class must list `self` as its first parameter: `def predict(self, x):`. If you write `def predict(x):`, calling `model.predict(x)` will raise `TypeError: predict() takes 1 positional argument but 2 were given`.
:::

:::caution[Forgetting `super().__init__()` when subclassing]
When inheriting from a framework base class like `torch.nn.Module`, forgetting to call `super().__init__()` at the start of `__init__` leaves the parent class's internal parameter registries uninitialized, causing cryptic runtime errors later.
:::

## Summary and further reading

**Key takeaways:**

- A class is a blueprint and an object is a concrete instance; `self` refers to the active instance executing a method.
- Always initialize instance-specific state inside `__init__` so objects remain independent in memory.
- The four pillars of OOP (Encapsulation, Inheritance, Polymorphism, Abstraction) form the architectural foundation of modern AI libraries (PyTorch, Scikit-Learn, Hugging Face).
- Dunder methods (`__len__`, `__getitem__`, `__call__`) let custom classes behave like native Python objects.
