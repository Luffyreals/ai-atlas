## Intuition

In data science and AI, real-world data never consists of isolated numbers—it comes in large collections: lists of thousands of images, dictionaries of millions of vocabulary words, or user feature vectors.

Imagine trying to find a book in a library:

1. **Method 1 (List):** Books are placed along a single long shelf without an index. To find a specific title, you have to walk from the beginning of the shelf to the end, checking one spine at a time. If the library holds 1 million books, you might have to inspect all 1 million of them.
2. **Method 2 (Hash Table – Dict / Set):** The library uses a hash index. You type the book's title into a terminal, and it immediately computes the exact shelf and slot number. You walk straight to that slot and pick up the book in a single step, whether the library holds 100 books or 100 million.

Choosing the right data structure not only keeps your code clean and readable—it is often the difference between a data loader that finishes in seconds and one that stalls for hours scanning lists.

## Theory

### The Four Core Data Structures

Python provides four built-in collection types:

| Structure | Syntax | Ordered? | Mutable? | Allows Duplicates? | Underlying Implementation |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **`list`** | `[1, 2, 3]` | Yes | Yes | Yes | Dynamic Array |
| **`tuple`** | `(1, 2, 3)` | Yes | **No** (Immutable) | Yes | Fixed-size Static Array |
| **`set`** | `{1, 2, 3}` | No | Yes | **No** (Unique only) | Hash Table |
| **`dict`** | `{"a": 1}` | Yes (since Python 3.7) | Yes | Unique keys | Hash Table |

### Hash Tables and Hashability

Why are membership lookups in `set` and `dict` so much faster than in `list`?

- When you insert an item into a `set` or a `key: value` pair into a `dict`, Python passes the key through a hash function: `hash(key)`.
- The hash function produces an integer that maps directly to a specific memory bucket.
- When you check `key in my_dict`, Python does not scan from start to finish; it hashes the key and jumps straight to the corresponding bucket in **$O(1)$** (constant) average time.

**Requirements for a Hashable Object:**
An object must be **immutable** throughout its lifetime so its hash value never changes.
- Hashable types: `int`, `float`, `str`, and `tuple` (provided all elements inside the tuple are also immutable).
- Unhashable types: `list`, `dict`, `set`. Trying to use a `list` as a dictionary key raises `TypeError: unhashable type: 'list'`.

### List Slicing

General slicing syntax: `sequence[start:stop:step]`

- `start`: Starting index (defaults to `0`).
- `stop`: Stopping index (exclusive—stops at `stop - 1`).
- `step`: Step size (a negative step reverses the traversal: `seq[::-1]`).
- Negative indices: `-1` refers to the last element, `-2` to the second-to-last.

Slicing is constantly used to split datasets into training/testing sets or mini-batches:

```python
train_data = all_data[:800]   # first 800 samples for training
test_data = all_data[800:]    # remaining samples for testing
```

### Comprehensions: Writing Concise and Efficient Code

Comprehensions let you construct a new list, dictionary, or set in a single expressive line that runs faster than manually calling `.append()` inside a `for` loop:

- **List comprehension:** `[f(x) for x in data if condition]`
- **Dict comprehension:** `{k: v for k, v in pairs}`
- **Set comprehension:** `{normalize(w) for w in text}`

### Shallow Copy vs. Deep Copy

When working with nested lists (such as 2D matrices or nested model configurations):

1. **Assignment (`b = a`):** Creates no copy at all! Both `a` and `b` point to the exact same object.
2. **Shallow copy (`b = a.copy()` or `b = a[:]`):** Creates a new outer list container, but its inner elements still point to the same nested objects. Mutating an inner sublist via `b` also mutates `a`!
3. **Deep copy (`import copy; b = copy.deepcopy(a)`):** Recursively clones every nested object at all levels, producing a completely independent copy.

## Illustration

Comparing sequential search in a dynamic array (`list`) against hash lookup in a hash table (`dict` / `set`):

```text
Lookup in a List (O(n) time complexity):
  Query: "cat"
  [0: "dog"] ──► [1: "bird"] ──► [2: "cat"] (Found after 3 sequential checks!)
   (With 1,000,000 items, worst-case lookup takes 1,000,000 checks)

Lookup in a Set / Dict (O(1) average time complexity):
  Query: "cat"
       │
       ▼
  [ Hash function hash("cat") ] ──► Computes memory bucket #42
       │
       ▼
  [ Bucket #42: "cat" ] (Jumps straight to the target slot in 1 step!)
```

## Common pitfalls

:::caution[The nested list multiplication trap]
When you initialize a 2D matrix using `matrix = [[0] * 3] * 3`, all 3 rows actually reference the exact same inner list object in memory. If you modify `matrix[0][0] = 1`, all 3 rows become `[1, 0, 0]`. Always use a list comprehension instead: `matrix = [[0] * 3 for _ in range(3)]`.
:::

:::caution[Mutating a collection while iterating over it]
Never call `.remove()` or `.pop()` to delete elements from a `list`, `set`, or `dict` while iterating directly over it in a `for` loop. Changing the collection size mid-iteration shifts internal indices, skipping elements or raising `RuntimeError: dictionary changed size during iteration`. Iterate over a copy or build a new filtered collection with a comprehension.
:::

:::caution[Using mutable types as dictionary keys]
Attempting to use a `list` as a `dict` key (such as `d[[1, 2]] = "point"`) immediately crashes with `TypeError: unhashable type: 'list'`. Whenever you need a composite coordinate or sequence as a key, convert it to an immutable `tuple`: `d[(1, 2)] = "point"`.
:::

## Summary and further reading

**Key takeaways:**

- `list` (mutable dynamic array) and `tuple` (immutable fixed array) store ordered sequential data.
- `set` (unique elements) and `dict` (key–value mappings) are backed by hash tables, providing $O(1)$ average lookup time.
- Dictionary keys and set elements must be hashable and immutable.
- Slicing and comprehensions keep data preprocessing and mini-batch partitioning concise and fast.
- Distinguish shallow copies (`copy()`) from deep copies (`deepcopy()`) whenever working with nested data structures.
