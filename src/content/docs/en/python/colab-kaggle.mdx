## Intuition

When starting out in artificial intelligence (AI), the biggest hurdle for beginners is rarely the algorithms themselves—it is **environment setup**: Python library version conflicts, NVIDIA CUDA driver installations, or memory configuration. If your personal computer lacks a powerful dedicated graphics card, training a deep neural network can take days.

To solve this problem, cloud platforms like **Google Colab** and **Kaggle** provide completely free computing environments right in your web browser:

- You do not need to install any software on your machine.
- The cloud servers come pre-installed with Python, NumPy, Pandas, Scikit-learn, PyTorch, and TensorFlow.
- You get access to high-performance **Graphics Processing Units (GPUs)** with just a few clicks.

Instead of typing code into long `.py` script files and rerunning everything from scratch whenever you fix a bug, you work inside interactive **notebooks**. You can break your program into small cells, test individual lines of code, immediately view data plots, and write explanatory notes right alongside your code.

## Theory

### Jupyter Notebook Architecture

A notebook file uses the `.ipynb` (Jupyter Notebook Format) extension. Every notebook consists of two main components:

1. **User Interface (Front-end):** The web browser that renders text blocks (Markdown cells) and executable code blocks (Code cells).
2. **Compute Engine (Kernel):** A background server process that executes your Python code and holds all variables, functions, and objects in RAM.

When you run a code cell (shortcut `Shift + Enter`), the browser sends that snippet to the kernel. The kernel performs the computation and sends the output (text, tables, charts) back to your screen.

### Google Colab vs. Kaggle Notebooks

Both platforms are built on Jupyter but are optimized for slightly different workflows:

| Feature | Google Colab | Kaggle Notebooks |
| :--- | :--- | :--- |
| **Provider** | Google Research | Kaggle (owned by Google) |
| **Free Hardware** | T4 GPU, CPU, TPU | Dual T4 GPU, P100, CPU |
| **GPU Quota** | Dynamic usage limits | ~30 hours/week |
| **Max Session Time** | 12 hours/session (90-min idle timeout) | 9 hours/session (12 hours on background submit) |
| **Data Storage** | Direct Google Drive mounting | One-click Kaggle Datasets attachment |
| **Best Suited For** | Learning, rapid prototyping, quick experiments | Data science competitions, sharing community projects |

### Shell Commands and Magic Commands

Inside a notebook environment, alongside standard Python code, you can interact directly with the virtual machine's Linux operating system through:

- **Shell Commands (`!`):** Run a single system command in a subshell. For example, `!pip install transformers` installs a package, and `!nvidia-smi` checks your allocated GPU specifications.
- **Line Magics (`%`):** Operate on a single line to configure or inspect the kernel environment:
  - `%pwd`: Print the current working directory.
  - `%cd /content/sample_data`: Change the kernel's active working directory.
  - `%time expression`: Measure the execution time of a single statement.
- **Cell Magics (`%%`):** Operate on the entire contents of the cell:
  - `%%time`: Measure the total execution time of the whole cell.
  - `%%writefile script.py`: Save the entire cell's contents to a file on disk.

### Ephemeral Storage and Data Persistence

Virtual machines on Colab and Kaggle run as **ephemeral runtimes**:

- The local disk at `/content` (on Colab) or `/kaggle/working` (on Kaggle) only exists while your current session is active.
- If you close your browser for too long, lose your internet connection, or hit the maximum session duration, the virtual machine is terminated and every downloaded or generated file on the local disk is wiped clean.
- **How to persist your data:**
  - On Colab: Mount your Google Drive with `from google.colab import drive; drive.mount('/content/drive')` and save model checkpoints to `/content/drive/MyDrive/...`.
  - On Kaggle: Click **Save Version** to commit and publish the notebook, which saves your output artifacts to Kaggle's persistent cloud storage.

## Illustration

The diagram below illustrates the communication flow between your web browser, the kernel server, and storage layers during a cloud notebook session:

```text
[ Web Browser ]
  │  (Write code, press Shift + Enter)
  ▼
[ Jupyter Server / Kernel (VM) ]
  ├── System RAM: Holds active variables, functions, and models
  ├── GPU Accelerator: Runs parallel matrix computations
  │
  ├── Ephemeral Disk (/content)
  │     └─► WIPED when the session disconnects or times out!
  │
  └── Persistent Storage
        ├─► Google Drive (Mounted via drive.mount)
        └─► Kaggle Dataset / Output Versions
```

A standard workflow for a cloud AI project:

1. **Initialize the runtime:** Select your hardware accelerator (Runtime $\to$ Change runtime type $\to$ T4 GPU).
2. **Load data:** Fetch files from an external source or mount your cloud storage directory.
3. **Run analysis:** Execute cells step by step to explore data and train your model.
4. **Save artifacts:** Export model checkpoints to persistent storage before closing your browser tab.

## Common pitfalls

:::caution[Confusing `!cd` with `%cd`]
When you run `!cd my_folder`, the system spawns a temporary subshell, changes into `my_folder`, and immediately exits that subshell. Your notebook's actual working directory does not change at all! To change the notebook kernel's working directory, always use the magic command `%cd my_folder`.
:::

:::caution[Losing hours of training by relying on ephemeral disk]
Many learners leave a model training overnight and let the browser disconnect. When they return the next morning, everything inside `/content` is gone. Always configure your training loop to save checkpoints directly to a mounted Google Drive folder or download key weight files as soon as training finishes.
:::

:::caution[Running cells out of order and corrupting variable state]
The top-to-bottom visual order of cells on your screen does not dictate the execution order in memory. The number inside the square brackets next to a code cell (such as `[5]`) shows when that cell was actually executed. If you edit cell 1 but forget to rerun it, cells below it will continue using the old value stored in RAM, leading to subtle and confusing bugs.
:::

## Summary and further reading

**Key takeaways:**

- Google Colab and Kaggle provide cloud-based Jupyter Notebook environments with free GPU acceleration.
- Notebooks separate the browser-based user interface from the background kernel process that executes code.
- Shell commands (`!`) run one-off operating system utilities, while magic commands (`%` and `%%`) configure and control the active kernel session.
- Local virtual machine disks are ephemeral; mount Google Drive or save a Kaggle Notebook version to keep your data safe.
