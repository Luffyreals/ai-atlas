## Intuition

You are searching for an apartment to rent. You survey rental prices of 10 apartments in your target neighborhood and summarize them in the table below. This dataset is used throughout this lesson.

<DatasetTable dataset="apartments" />

### Hand-coded rules vs learning from examples

The first approach is **hand-crafting deterministic rules**, such as estimating "each square meter costs around 200 000 VND". However, this 200 000 VND rate is an educated guess. To account for location, floor level, and interior furnishings, you would have to manually devise additional rules for every nuance, and adjust them by hand whenever market prices shift.

The second approach is **feeding examples to the machine**: provide the 10 apartments, each with its actual floor area and verified rent. The machine discovers the underlying pattern mapping area to price on its own, and then applies that learned pattern to predict the rent of a new 65 m² unit. When new market listings become available, you simply re-train the algorithm on the updated dataset. That is the core philosophy of **machine learning**. Tom Mitchell's foundational textbook *Machine Learning* (1997) defines the discipline as the study of computer algorithms that improve automatically through experience. Here, "experience" is your data.

Machine learning is already embedded in everyday technology: movie recommendations, email spam filters, facial recognition in photos, and language translation. These are all tasks where hand-crafting explicit rule sets is nearly impossible, but abundant training examples exist.

### Memorizing is not learning

Suppose a machine finishes its training run. How can you verify that it truly learned? If a student practices a single math exam until they memorize every single answer by heart, scoring 10/10 on that identical exam does not prove mathematical understanding. To assess true proficiency, you must present a **fresh exam with unseen problems**.

The same holds true for computer models. A model could achieve zero error across all 10 surveyed apartments simply by storing their prices in a lookup table. Yet you already know the rent for those 10 apartments. What you actually need is accurate predictions for the upcoming 65 m² apartment that the model has never encountered before.

The core question of this lesson is: **how does a machine extract patterns from examples, and how can we verify that these learned patterns hold true on unseen data.**

## Theory

### Three families of machine learning

Machine learning is a subfield of artificial intelligence (AI), and deep learning is in turn a specialized subfield of machine learning: three concentric concepts, rather than separate disciplines. Machine learning itself is commonly categorized by the **learning signal available to the algorithm**:

- **Supervised learning**. Every example contains both input features and the corresponding ground-truth answer, called a **label**, as shown in the apartment dataset: the input feature is floor area, and the label is monthly rent. The model learns the mapping from inputs to labels. "Supervised" denotes guidance by known target labels, not active human supervision.
- **Unsupervised learning**. The dataset consists solely of input features without target labels. The algorithm uncovers latent structure on its own, such as **clustering**: grouping customer profiles with similar shopping patterns without predefined category lists.
- **Reinforcement learning**. An **agent** interacts with an external **environment**, receives scalar feedback in the form of positive or negative **rewards**, and learns a decision policy that maximizes cumulative reward over time, similar to an algorithm learning to play a video game. Advanced AI systems such as AlphaGo combine both supervised and reinforcement learning techniques.

The figure below summarizes the three primary families. Notice the second row of each card: the fundamental distinction lies in what signal the machine learns from.

There is also **semi-supervised learning**: only a small subset of the training corpus is labeled, which is common when annotation is expensive, such as medical scans requiring expert radiologist review. The remainder of this lesson focuses on supervised learning.

### Notation in supervised learning

These mathematical conventions apply across the entire Machine Learning section.

Each individual data record is called a **sample** (or instance). A sample has measurable attributes called **features**, which represent the variables fed into the model, such as floor area, number of bedrooms, and building floor. The features of a single sample form a column vector $\mathbf{x}$:

$$
\mathbf{x} = [x_1, x_2, \dots, x_n]^\top
$$

- $n$ denotes the **number of features**. $x_j$ represents feature $j$.
- $y$ is the ground-truth **label** for that sample.
- $m$ is the total **number of samples**. The $i$-th sample is denoted as $\left(\mathbf{x}^{(i)}, y^{(i)}\right)$. The superscript $(i)$ indexes sample $i$, rather than an algebraic exponent.

In our apartment dataset, $m = 10$ and $n = 1$: each unit is described by a single feature, its floor area. The first apartment has $\mathbf{x}^{(1)} = [25]$ and $y^{(1)} = 6.7$. Different textbooks may adopt alternative notation, such as using $N$ for sample count.

A **model** is a parameterized mathematical function $f$ that maps inputs to predictions:

$$
\hat{y} = f(\mathbf{x})
$$

$\hat{y}$ (pronounced "y-hat") represents the **predicted value**, distinguished from the ground-truth target $y$.

The prediction error of $f$ is quantified by a **loss function**, denoted as $\mathcal{L}$: a scalar measure computed over pairs of predictions $\hat{y}^{(i)}$ and actual targets $y^{(i)}$, where larger discrepancies produce higher loss values. For regression tasks, the standard metric is the **mean squared error** (MSE): the arithmetic mean of squared prediction errors. The [Linear Regression](/en/ml/linear-regression/) lesson explains why squaring is standard practice.

**Training** is the algorithmic process of selecting an optimal function $f$, from a chosen hypothesis class, such that the loss $\mathcal{L}$ over observed data is minimized. The hypothesis class may be the set of all straight lines, or a much richer family of non-linear functions. The internal values adjusted during training to configure $f$ are known as model **parameters**. Note that some algorithms operate differently: the `fit` method of K-Nearest Neighbors (KNN) in the code section simply stores the training instances, performing local nearest-neighbor lookups only at prediction time.

:::note[Takeaway]
Supervised learning: given $m$ samples $\left(\mathbf{x}^{(i)}, y^{(i)}\right)$, each with $n$ features, determine a mapping function $f$ such that predictions $\hat{y} = f(\mathbf{x})$ approximate target values $y$, with goodness of fit quantified by a loss function $\mathcal{L}$.
:::

### Regression and classification

Supervised learning encompasses two primary problem paradigms, distinguished by the **data type of the target label** $y$:

- **Regression**: the target label is a continuous numerical quantity that can take infinitely many real values. Examples include predicting apartment rents, tomorrow's temperature, or next quarter's revenue.
- **Classification**: the target label is a discrete categorical outcome from a predefined set of classes. Examples include detecting spam vs non-spam, identifying a photo as a dog or cat, or predicting loan default vs timely repayment. While class labels are often encoded numerically (such as 0 and 1), these integers serve purely as category identifiers rather than continuous measurements, preserving the classification nature of the problem.

The same apartment dataset can frame both tasks: predicting exact rental price in million VND is regression, whereas grouping rents into categorical bins such as "expensive" (10 million VND or higher) versus "affordable" turns the problem into binary classification, despite identical input features. The first code example implements this exact comparison.

### The workflow: data, training, evaluation

A standard supervised learning project follows a structured sequence of stages:

1. **Collect labeled data**, such as 10 apartment records with confirmed rents.
2. **Partition the data immediately**, using random sampling, into a **training set** for model learning and a held-out **test set** for final evaluation.
3. **Train exclusively on the training set.** The model must never observe any test samples during fitting.
4. **Evaluate on the test set**: compare predictions against ground-truth targets using an objective metric such as MSE.
5. **Deploy the model** on newly incoming production data, provided performance benchmarks are satisfied.

The test set functions as the "unseen exam" introduced in our intuitive thought experiment.

### Generalization

**Generalization** is a model's ability to perform accurately on new, previously unseen inputs that were not part of the training distribution. This represents the ultimate objective of machine learning. In-sample training error is almost always **optimistic**, because model parameters were directly optimized to minimize loss on those specific samples. A sufficiently flexible model can easily drive training error to zero by brute-force memorization, while failing catastrophically on fresh inputs. Because the test set is held out during training, test error provides an **unbiased estimate** of out-of-sample performance.

When a model exhibits very low training error but substantially higher test error, it has learned spurious statistical noise and accidental idiosyncrasies specific to the training set. This failure mode is called **overfitting**, which is thoroughly analyzed in our dedicated Overfitting and Underfitting lesson.

A rigorous test set must be sufficiently large, representative of production deployment conditions, and completely isolated from the training distribution.

### Limitations

- **Small test sets produce high-variance performance estimates.** With only 10 total apartment samples, holding out 30% leaves just 3 test units (as shown in our second code cell).
- **Test sets suffer wear and tear when reused repeatedly** for hyperparameter tuning or architectural modifications (addressed in our Common Pitfalls section). Mitigating this requires a separate **validation set**, introduced in subsequent lessons.
- **Models can only learn from the data distribution they observe.** If training data is biased or unrepresentative, both model predictions and evaluation scores will be skewed. Extrapolating beyond observed feature boundaries frequently results in erroneous predictions, as detailed in the [Linear Regression](/en/ml/linear-regression/) lesson.

Performance under the primary split from our illustration (test set containing the 42, 75, and 48 m² apartments):

| Model | Train MSE | Test MSE |
|---|---:|---:|
| Linear Regression | 0.2190 | 1.0007 |
| 1-NN Memorization | 0.0000 | 2.6267 |

Judged solely by training error, the 1-NN memorization baseline appears flawless: its train MSE is exactly 0.0000, since the nearest neighbor of any training sample is itself. Yet on the 3 unseen test apartments, its MSE is approximately 2.6 times higher than the linear model. It blindly memorizes the individual idiosyncrasies of neighbor samples (such as floor level or furnishings). Almost the entire test error stems from the 48 m² unit: its nearest training neighbor is a 55 m² unit costing 12.2 million VND, whereas the true rent is only 9.4 million VND. The linear model, by contrast, captures the overarching trend that larger floor area generally commands higher rent.

Now consider the final comparison across different random splits. This highlights a critical lesson in machine learning evaluation:

| Split seed | Test apartments (m²) | Linear Regression Test MSE | 1-NN Memorization Test MSE |
|---|---|---:|---:|
| `random_state=4` | 42, 75, 48 | 1.0007 | 2.6267 |
| `random_state=8` | 75, 60, 85 | 0.6799 | 2.4567 |
| `random_state=2` | 48, 30, 55 | 0.7327 | 0.1467 |

Using identical models and identical datasets, merely altering which 3 apartments land in the test set causes the linear model's test MSE to swing between 0.68 and 1.00, while the memorization model drops from 2.63 all the way down to 0.15. Under `random_state=2`, the memorization model actually **outperforms** linear regression, because the nearest training neighbors happen to differ in rent by only 0.2 to 0.6 million VND. Because test MSE averages just three error terms here, a single fortunate or unfortunate sample heavily shifts the score.

Consequently, with only 10 samples, a single train/test split is **insufficient** to draw definitive conclusions about model superiority. Real-world machine learning applications typically involve hundreds of thousands or millions of samples, providing sufficiently large test sets for stable error estimation. When working with small datasets, practitioners utilize cross-validation (repeating splits multiple times and averaging results), covered in upcoming lessons.

## Common pitfalls

:::caution[Evaluating a model on the data it was trained on]
In our second code cell, the 1-NN baseline achieves a train MSE of 0.0000, yet its test MSE on unseen apartments is 2.6 times higher than linear regression. In-sample training score only reflects how thoroughly an algorithm memorized historical inputs. Always partition a test set **prior to** model fitting, and assess predictive quality based on held-out test metrics.
:::

:::caution[Letting test data leak into training]
A test set provides an honest evaluation only when the model has never encountered it during development. Two subtle issues frequently compromise this boundary:

- **Duplicate samples.** An identical apartment record appears twice in the raw data, landing once in training and once in testing. The model correctly predicts the test instance simply by recalling the duplicate training instance.
- **Selecting models using the test set.** Testing a configuration, examining test error, tweaking hyperparameters, and repeating the cycle. After multiple iterations, the chosen model inevitably overfits the nuances of those specific test samples, resulting in overly optimistic evaluation scores. Always conduct model selection and hyperparameter tuning on an independent validation set, reserving the test set exclusively for final verification.

These flaws are categorized as **data leakage**. The standard defense: partition the test set immediately upon data ingestion, and treat it as non-existent until final evaluation.
:::

:::caution[Guessing problem type from the algorithm's name]
Logistic regression contains the word "regression" in its name, yet is fundamentally a **classification** model. Conversely, algorithms like K-Nearest Neighbors natively handle both tasks (`KNeighborsClassifier` and `KNeighborsRegressor`). Always inspect target variable $y$: if it represents a continuous measurement (price, temperature), the problem is regression; if it represents discrete categories, even if encoded as 0 and 1, the problem is classification.
:::

## Summary and further reading

**Key takeaways:**

- Machine learning enables computers to extract predictive rules directly from data examples. The three primary paradigms are supervised learning (learning from ground-truth labels), unsupervised learning (discovering intrinsic structure), and reinforcement learning (learning from sequential rewards).
- Supervised learning maps $m$ samples $\left(\mathbf{x}^{(i)}, y^{(i)}\right)$ with $n$ input features to predictions $\hat{y} = f(\mathbf{x})$ that minimize a loss function $\mathcal{L}$. Target variables representing continuous measurements define regression; categorical targets define classification.
- Standard machine learning workflow: hold out a test set upfront, fit parameters strictly on the training set, and evaluate out-of-sample performance on the test set. In scikit-learn, this maps directly to `train_test_split`, `fit`, and `predict`.
- The primary goal of learning is generalization. Training scores are inherently optimistic; memorization baselines can achieve perfect training accuracy while performing poorly on new inputs. Small test sets introduce high variance in error estimation.
