:::tip[Quick refresher]
The Deep Learning lessons on Convolutional Neural Networks (CNNs) and Modern CNN Architectures are not published yet, so here is a brief summary of what this lesson uses. An image is an array of numbers; **convolution** slides a small matrix called a **kernel** (or filter, e.g. $3 \times 3$) across the image, multiplies overlapping cells at each position, sums them into a single number, and arranges those numbers into a **feature map**. A layer has multiple kernels, each producing one feature map; the number of maps is the number of output **channels**, just as an RGB image has 3 channels (R, G, B). Convolution is typically followed by a ReLU activation, $\max(0, x)$, and **pooling**: $2 \times 2$ max pooling keeps the largest value in each $2 \times 2$ block, halving the height and width of the map. The numbers inside the kernels are model parameters learned via **backpropagation** and [gradient descent](/en/ml/gradient-descent/), just like the weights of a standard neural network.
:::

## Intuition

### The problem: one image in, one label out

You have an $8 \times 8$ image of a handwritten digit and want the computer to tell you which digit it is. Or you have a $224 \times 224$ photograph and want the computer to say whether it shows a cat, a dog, or a teapot. That is **image classification**: the input is an image, and the output is a single label chosen from a fixed list of classes.

This task has a famous proving ground: the [ImageNet Large Scale Visual Recognition Challenge](https://arxiv.org/abs/1409.0575) (ILSVRC, Russakovsky et al., 2015), held annually starting in 2010. Its classification track has 1,000 classes and roughly 1.2 million training images. All five networks in the title of this lesson are milestones along that path.

### A naive attempt: flattening the image

The first approach anyone might try is to flatten the image into one long vector and feed it into a standard neural network. A $224 \times 224 \times 3$ image has 150,528 numbers. A single fully connected layer with just 1,000 output neurons already requires roughly 150 million weights.

Worse still is how it handles position. Each weight is tied to **one** fixed pixel. A cat in the top-left corner and a cat in the bottom-right corner pass through two completely different sets of weights. The network would have to relearn "what a cat ear looks like" separately at every location in the image.

### Two observations about images

- **Locality.** Detecting an edge, a stroke, or a corner only requires looking at a few neighboring pixels. There is no need to connect a pixel in the top corner to one in the bottom corner in the very first layer.
- **Stationarity (patterns repeat everywhere).** A vertical edge on the left looks just like a vertical edge on the right. So we can apply the **exact same** filter at every position.

Picture a small magnifying glass tuned to spot one specific stroke pattern. You slide it across a page and record wherever it "lights up." That is a single kernel. A collection of magnifying glasses, each looking for a different stroke, forms a convolutional layer. Stack many layers together: the early layers detect edges, the middle layers combine edges into curves and corners, then into eyes and ears, and finally into a cat.

The central question of this lesson is: **how do we build a model that takes an image as input, uses few parameters, recognizes the same pattern anywhere, and is deep enough to assemble small strokes into whole objects—and then how do we make it deeper and more accurate while keeping it fast?**

## Theory

### Problem formulation

An image is $\mathbf{X} \in \mathbb{R}^{H \times W \times C}$: height $H$, width $W$ pixels, and $C$ channels ($C = 1$ for grayscale, $C = 3$ for color). A CNN is a parameterized function $f_{\boldsymbol{\theta}}$ that maps the image to a vector of **logits**, one score per class. Softmax turns the logits into probabilities, and the class with the highest probability is the prediction $\hat{y}$. Training chooses $\boldsymbol{\theta}$ to minimize the cross-entropy loss $\mathcal{L}$ over the training set.

ILSVRC evaluates models using **top-5 error**: a prediction counts as correct if the true label appears among the 5 classes with the highest predicted probabilities. This is because many photos contain more than one object, and the 1,000 classes include many fine-grained distinctions (such as dozens of dog breeds).

### Single-channel convolution

Take a single-channel image $\mathbf{X}$ and a $k \times k$ kernel $\mathbf{K}$. The value at cell $(i, j)$ of the output feature map $\mathbf{F}$ is:

$$
F_{i,j} = \sum_{u=0}^{k-1} \sum_{v=0}^{k-1} X_{i+u,\; j+v}\, K_{u,v} + b
$$

In plain words: place the top-left corner of the kernel at cell $(i, j)$ of the image, multiply each pair of overlapping cells, sum all $k^2$ products, and add a scalar bias $b$. Indices start at 0, matching NumPy and the code example below.

Consider a vertical-edge kernel:

$$
\mathbf{K} = \begin{bmatrix} 1 & 0 & -1 \\ 1 & 0 & -1 \\ 1 & 0 & -1 \end{bmatrix}
$$

It subtracts the sum of the right column of the window from the sum of the left column. A flat region (both columns equal) yields 0. A region that is dark on the left and bright on the right yields a negative number; bright on the left and dark on the right yields a positive number. Thus the feature map "lights up" along vertical edges, and the sign tells you which way the brightness transitions.

Mathematically, the formula above is **cross-correlation**: true convolution flips the kernel both horizontally and vertically before sliding. Deep learning libraries do not flip the kernel, even though they call the operation convolution; since the kernel weights are learned from data, flipping makes no difference.

### Multiple input and output channels

A color image has $C_{\text{in}} = 3$ channels. Each kernel then has shape $k \times k \times C_{\text{in}}$: it spans all three input channels at once, and the sum in the formula runs over the channel axis as well. One kernel still produces **one** 2D feature map. A layer with $C_{\text{out}}$ kernels produces $C_{\text{out}}$ maps, meaning the output has $C_{\text{out}}$ channels.

Counting parameters: each kernel has $k^2 C_{\text{in}}$ weights plus one bias term, and there are $C_{\text{out}}$ kernels, giving

$$
\text{parameters} = k^2\, C_{\text{in}}\, C_{\text{out}} + C_{\text{out}}
$$

Notice that this count **does not depend on the image size** $H \times W$: the exact same kernels slide over a small image or a high-resolution image.

Compare this with a fully connected layer that maps a $32 \times 32 \times 3$ image to 16 feature maps of size $32 \times 32$. A fully connected layer links every output value to every input value, requiring $(32 \cdot 32 \cdot 3) \cdot (32 \cdot 32 \cdot 16) = 50,331,648$ weights. A $3 \times 3$ convolutional layer needs only $3^2 \cdot 3 \cdot 16 = 432$ weights (the second code cell prints both numbers)—roughly 116,000 times fewer. The two observations from the Intuition section are the exact two sources of savings: **locality** (each output looks at 27 inputs instead of 3,072) and **weight sharing** (every spatial position reuses the same kernel).

Weight sharing also gives another property: shifting the input image shifts the feature map by the exact same amount (**translation equivariance**). A pattern is recognized regardless of where it appears.

### Output dimensions

Two more hyperparameters control how the kernel slides. **Padding** $p$ adds $p$ rows and columns of zeros around the border of the image. **Stride** $s$ moves the kernel by $s$ cells at a time instead of 1.

Along one dimension, the padded image has length $H + 2p$. The top (or left) edge of the window can land at positions $0, s, 2s, \dots$ as long as the window fits inside the padded image—meaning its starting index cannot exceed $H + 2p - k$. The number of valid positions is the number of steps of size $s$ that fit in that range, plus 1 for position 0:

$$
H' = \left\lfloor \frac{H + 2p - k}{s} \right\rfloor + 1
$$

The floor $\lfloor \cdot \rfloor$ appears because the final step may fall short of a full window, and any leftover border pixels are dropped. The output width $W'$ follows the exact same formula. For an $8 \times 8$ image with $k = 3$:

| Padding $p$ | Stride $s$ | Output size |
|---:|---:|---|
| 0 | 1 | $6 \times 6$ |
| 1 | 1 | $8 \times 8$ (preserves size) |
| 0 | 2 | $3 \times 3$ |
| 1 | 2 | $4 \times 4$ |

Pooling uses the exact same formula: $2 \times 2$ max pooling with $s = 2, p = 0$ gives $\lfloor (H - 2)/2 \rfloor + 1 = H/2$ when $H$ is even. VGG uses $k = 3, p = 1, s = 1$ for every convolutional layer to preserve spatial dimensions, leaving all downsampling to pooling: $224 \to 112 \to 56 \to 28 \to 14 \to 7$.

### Receptive field

How many original image pixels does a single cell in a feature map "see"? That region is called its **receptive field**. After one $3 \times 3$ layer, each cell sees a $3 \times 3$ patch of pixels. Stack a second $3 \times 3$ layer on top: each cell in the second layer looks at $3 \times 3$ cells of the first layer, which overlap and each look at $3 \times 3$ pixels, covering a $5 \times 5$ region in total. Every $k \times k$ layer with stride 1 widens the receptive field by $k - 1$:

$$
r_L = 1 + L\,(k - 1)
$$

When earlier layers use a stride greater than 1, subsequent steps cover even more ground because each cell in a deeper layer corresponds to multiple pixels in the input. If layer $l$ has kernel size $k_l$ and stride $s_l$:

$$
r_L = 1 + \sum_{l=1}^{L} (k_l - 1) \prod_{m=1}^{l-1} s_m
$$

The product of preceding strides tells you how many input pixels correspond to a single step at layer $l$. Take the small CNN in the PyTorch code cell: a $3 \times 3$ conv (receptive field 3), $2 \times 2$ max pooling with stride 2 (adds $1 \cdot 1$, reaching 4), another $3 \times 3$ conv after a stride of 2 (adds $2 \cdot 2$, reaching 8), and another pooling layer (adds $1 \cdot 2$, reaching 10). Each cell of the final feature map sees a $10 \times 10$ region—wider than the entire $8 \times 8$ digit image (with the overhang falling on padding). That is how a deep network "sees" large objects even though every individual kernel is just $3 \times 3$.

:::note[Key takeaway]
A convolutional layer has $k^2 C_{\text{in}} C_{\text{out}} + C_{\text{out}}$ parameters, independent of image resolution. Its output size along each dimension is $\lfloor (H + 2p - k)/s \rfloor + 1$. Stacking small layers grows the receptive field linearly; stride and pooling make it grow multiplicatively.
:::

### AlexNet (2012): deep networks on GPUs

AlexNet (Krizhevsky, Sutskever, and Hinton, 2012) has 5 convolutional layers and 3 fully connected layers, totaling roughly 60 million parameters. Its first layer applies 96 kernels of size $11 \times 11 \times 3$ with stride 4 on $224 \times 224$ images. At ILSVRC-2012, a variant achieved a top-5 error of 15.3%, while the runner-up stood at 26.2%.

According to the paper, the breakthrough came from using **ReLU** instead of $\tanh$ (training several times faster), **dropout** and **data augmentation** (random crops and horizontal flips) to curb overfitting, and training across two GTX 580 GPUs for 5 to 6 days. Most of its parameters live in the final fully connected layers, just as our parameter count formula predicts: the torchvision implementation has about 2.5 million parameters in the convolutional backbone and 58.6 million in the classifier head.

### VGG (2014): only $3 \times 3$ kernels

VGG (Simonyan and Zisserman, 2014; published at ICLR 2015) asked: what if we use only the smallest kernel that can still capture left/right and up/down—namely $3 \times 3$—and stack many layers deep? The resulting networks have 16 to 19 weight layers, where every convolution uses $k = 3, s = 1, p = 1$, interleaved with 5 max-pooling layers. VGG won first place in localization and second place in classification at ILSVRC 2014.

Why are three stacked $3 \times 3$ layers better than a single $7 \times 7$ layer? By our receptive field formula, three $3 \times 3$ layers cover $1 + 3 \cdot 2 = 7$ pixels per side, matching a $7 \times 7$ layer. Yet with $C$ input and output channels:

$$
3 \cdot (3^2 C^2) = 27 C^2 \quad \text{vs.} \quad 7^2 C^2 = 49 C^2
$$

A single $7 \times 7$ layer costs 81% more parameters. Moreover, stacking three layers inserts three ReLU nonlinearities instead of one, making the composite function more expressive. The catch: VGG-16 has roughly 138 million parameters (again mostly in its fully connected layers) and costs about 15.3 billion multiply-adds per image.

### ResNet (2015–2016): residual blocks

If deeper is better, can we just keep stacking layers? He et al. (2016) observed the opposite. On CIFAR-10, a plain 56-layer network had higher error **on the training set itself** than a 20-layer network. This is not overfitting (where training error is low and test error is high); the authors called it the **degradation** problem.

Their reasoning went as follows: take a trained shallow network and stack extra layers on top that simply perform an **identity mapping** (output equals input). This deeper network would produce the exact same predictions as the shallow one, proving that a deeper model has at least one solution no worse than the shallow model. Yet gradient descent fails to find it: fitting an identity mapping through a stack of nonlinear layers turns out to be surprisingly hard.

Their fix: let $H(\mathbf{x})$ be the target mapping a few stacked layers should learn. Instead of fitting $H$ directly, let the layers fit the **residual** $F(\mathbf{x}) = H(\mathbf{x}) - \mathbf{x}$, and add the original input back via a **residual connection** (or shortcut):

$$
\mathbf{y} = F(\mathbf{x}) + \mathbf{x}
$$

If the identity mapping is optimal, the layers only need to drive their weights toward zero so that $F(\mathbf{x}) \approx \mathbf{0}$, which is much easier. Adding extra blocks no longer hurts training error. An identity shortcut adds zero parameters and almost no compute (just an element-wise addition). When the number of channels or spatial size changes, the shortcut uses a $1 \times 1$ convolution to match dimensions.

A complementary view from the same group's follow-up paper (He et al., 2016, "Identity Mappings") notes that because the derivative of $\mathbf{x}$ with respect to itself is the identity matrix, gradients have an unimpeded highway backward through the additions from the final layer all the way to the early layers.

Networks of 50 layers or more use a "bottleneck" block ($1 \times 1 \to 3 \times 3 \to 1 \times 1$) that squeezes the channel count, applies the $3 \times 3$ convolution, and expands the channels back to save compute. ResNet-152 has 152 layers—8 times deeper than VGG-19—yet requires only 11.3 billion multiply-adds, fewer than VGG-16. An ensemble of ResNets achieved a 3.57% top-5 error and won first place in ILSVRC 2015 classification.

### MobileNet (2017): splitting convolution in two

By this point CNNs were accurate, but far too heavy for mobile phones. MobileNet (Howard et al., 2017) replaces each standard convolution with a **depthwise separable convolution**, which factors the operation into two steps:

1. **Depthwise convolution:** each input channel gets its **own** single $k \times k$ kernel that filters only within that channel. It filters spatially without mixing channels.
2. **Pointwise convolution:** a $1 \times 1$ convolution mixes the $C_{\text{in}}$ channels into $C_{\text{out}}$ channels. It mixes channels without looking at spatial neighbors.

Standard convolution does both jobs in a single step. Let's count the multiply-adds for an output feature map of size $H' \times W'$: each of the $H'W'C_{\text{out}}$ output values in a standard convolution costs $k^2 C_{\text{in}}$ operations, whereas the two separated steps cost $k^2$ operations for each of the $H'W'C_{\text{in}}$ intermediate values plus $C_{\text{in}}$ operations for each of the $H'W'C_{\text{out}}$ final values:

$$
\begin{aligned}
\text{standard} &= k^2\, C_{\text{in}}\, C_{\text{out}}\, H'W' \\
\text{separable} &= k^2\, C_{\text{in}}\, H'W' + C_{\text{in}}\, C_{\text{out}}\, H'W'
\end{aligned}
$$

Dividing the bottom line by the top line cancels $C_{\text{in}} H'W'$, leaving:

$$
\frac{\text{separable}}{\text{standard}} = \frac{k^2 + C_{\text{out}}}{k^2\, C_{\text{out}}} = \frac{1}{C_{\text{out}}} + \frac{1}{k^2}
$$

With $k = 3$ and $C_{\text{out}}$ in the hundreds, $1/C_{\text{out}}$ is tiny and the ratio is close to $1/9$—an 8x to 9x reduction. For the example from the paper (computed in the second code cell), a $14 \times 14$ map with 512 input and output channels requires 462.4 million multiply-adds with standard convolution, versus just 52.3 million with depthwise separable convolution. Parameter counts drop by the exact same ratio (just drop $H'W'$ from both lines). The full MobileNet has 4.2 million parameters, 569 million multiply-adds, and 70.6% top-1 accuracy on ImageNet. Two hyperparameters—a width multiplier $\alpha$ (scaling channel counts) and a resolution multiplier $\rho$ (scaling image size)—let you shrink the model even further.

Follow-up versions, MobileNetV2 (Sandler et al., 2018) and MobileNetV3 (Howard et al., 2019), added inverted residual connections and neural architecture search.

### EfficientNet (2019): scaling all three dimensions together

When you have a larger compute budget, along which dimension should you scale up a CNN: deeper (more layers, depth $d$), wider (more channels, width $w$), or higher input resolution $r$? Tan and Le (2019) noted that compute scales linearly with $d$, but quadratically with $w^2$ and $r^2$: doubling the channels doubles both $C_{\text{in}}$ and $C_{\text{out}}$, and doubling the image side quadruples $H'W'$.

They observed that scaling any single dimension alone quickly hits diminishing returns, and proposed **compound scaling** governed by a single coefficient $\phi$:

$$
d = \alpha^{\phi}, \quad w = \beta^{\phi}, \quad r = \gamma^{\phi}, \qquad \alpha \cdot \beta^2 \cdot \gamma^2 \approx 2
$$

The constraint $\alpha \beta^2 \gamma^2 \approx 2$ ensures that total compute—proportional to $d \cdot w^2 \cdot r^2 = (\alpha \beta^2 \gamma^2)^{\phi}$—grows by roughly $2^{\phi}$, doubling with each integer step in $\phi$. A small grid search on the baseline model found $\alpha = 1.2$, $\beta = 1.1$, $\gamma = 1.15$ (where $\alpha\beta^2\gamma^2 \approx 1.92$).

The baseline network, EfficientNet-B0, was found via neural architecture search using MobileNetV2's inverted residual blocks (MBConv) with squeeze-and-excitation. B0 has 5.3 million parameters, 0.39 billion multiply-adds, and 77.1% top-1 accuracy. Scaling $\phi$ up produces B1 through B7; according to the paper, B7 reaches 84.3% top-1 accuracy while being 8.4x smaller and 6.1x faster than the best prior CNN.

### Reusing pretrained networks

In practice, you rarely train these architectures from scratch. **Transfer learning** takes a network pretrained on ImageNet and replaces its final classification layer with a new layer matching the number of classes in your task. Following the [PyTorch transfer learning tutorial](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html), two approaches are standard: **freezing** all convolutional layers and training only the new linear head, or fine-tuning the entire network with a small learning rate $\eta$. Transfer learning works because early layers learn general-purpose features—edges, colors, and textures—that are useful across almost any visual domain.

### Limitations

- **Convolution is local.** Long-range relationships between distant regions only emerge in deep layers. [Image Classification with Transformers](/en/cv/vision-transformer/) lets every image patch attend to every other patch right from the first layer.
- **Parameter count does not equal wall-clock speed.** MobileNet uses very few multiply-adds, but actual latency depends heavily on hardware memory bandwidth and library support for depthwise operations.
- **Whole-image classification only.** Assigning a class label to every individual pixel is covered in [Semantic Segmentation](/en/cv/semantic-segmentation/); diversifying training images is covered in [Image Augmentation](/en/cv/image-augmentation/).

## Common pitfalls

:::caution[Forgetting padding and stride when computing output shapes]
A "shape mismatch" error at the first linear layer almost always comes from miscalculating the spatial size of the feature map before it. Track each layer's size using $\lfloor (H + 2p - k)/s \rfloor + 1$, including pooling layers, or print the intermediate shape before training as our small CNN script does with `feature maps`. Also remember that PyTorch orders tensor axes as $(N, C, H, W)$: batch, channel, height, width. An $8 \times 8$ grayscale image still needs an explicit channel axis of size 1—`(1, 8, 8)`—which is why the script calls `unsqueeze(1)`.
:::

:::caution[Thinking ResNet was invented to fix vanishing gradients or overfitting]
The ResNet paper explicitly shows that plain deep networks suffer from higher **training error**, ruling out overfitting. Their plain networks already used batch normalization, and the authors verified that gradients had healthy norms rather than vanishing. The core insight is optimization ease: with a residual shortcut, learning to "do nothing" only requires pushing weights toward zero, so extra layers do not hurt. The "unimpeded gradient highway" perspective came from their follow-up paper as a complementary explanation, not the original motivation.
:::

:::caution[Confusing deep learning's convolution with mathematical convolution]
`torch.nn.Conv2d` computes cross-correlation without flipping the kernel, whereas `scipy.signal.convolve2d` flips the kernel. When comparing against a signal-processing library, use `correlate2d` as our NumPy example does. For a learned network this distinction does not matter, but if you plug in a hand-crafted filter (such as an edge detector) using the wrong convention, the signs of your output can be inverted.
:::

## Summary and further reading

**Key takeaways:**

- Convolution slides a small kernel across an image: local connectivity and weight sharing mean a layer needs only $k^2 C_{\text{in}} C_{\text{out}} + C_{\text{out}}$ parameters regardless of image size, and recognizes patterns anywhere.
- Output size along each dimension is $\lfloor (H + 2p - k)/s \rfloor + 1$. Stacking small kernels grows the receptive field linearly, $r_L = 1 + L(k - 1)$ when stride is 1.
- AlexNet (2012) brought deep CNNs to GPUs; VGG (2014) stacked uniform $3 \times 3$ kernels; ResNet (2015–2016) introduced residual blocks $\mathbf{y} = F(\mathbf{x}) + \mathbf{x}$ to train networks over a hundred layers deep.
- MobileNet (2017) factored convolution into depthwise and pointwise steps, cutting cost to roughly $1/C_{\text{out}} + 1/k^2$; EfficientNet (2019) scaled depth, width, and resolution together via a single compound coefficient $\phi$.
