## Intuition

### From "what is in this image" to "what is this pixel"

An image classifier looks at a street photo and says: "car." For a self-driving car, that answer is useless. The vehicle needs to know **where the car is, how far the drivable road extends, and which exact pixels mark the curb**. A radiologist reading a CT scan faces the same need: knowing "there is a tumor" is not enough; measuring its volume requires tracing its exact boundary.

Semantic segmentation answers that question for **every single pixel**: this pixel is road, that pixel is pedestrian, the one above is sky. The output is a color-coded map of the exact same height and width as the input image. Note that two pedestrians standing side by side are painted with the exact same "person" color: semantic segmentation does not separate individual instances of the same class. Telling individual objects apart is the job of [Instance and Universal Segmentation](/en/cv/instance-universal-segmentation/).

### The tension between "what" and "where"

Suppose you take a classification CNN and strip off its final linear layer. You immediately hit two opposing problems:

- **Deep layers are spatially coarse.** After five 2x downsampling stages, the feature grid is $1/32$ the size of the image. Each cell on a $7 \times 7$ grid corresponds to a $32 \times 32$ pixel patch: it knows "there is a cat here," but has lost where the cat's ear ends and the background begins.
- **Shallow layers are semantically blind.** Feature maps in the first few layers preserve crisp edges and exact pixel coordinates, but their small receptive fields only see local edges and color blobs—not enough context to tell a cat from a dog.

Think of two maps: a world atlas tells you which country you are in, but cannot show you a back alley. A neighborhood street map shows every alley, but without the atlas you have no idea which country the neighborhood belongs to. A good navigator uses **both**.

All five architectures in this lesson are five distinct ways to fuse those two sources of information. Our central question is: **how do we build a network that takes an $H \times W$ image and predicts a class for every pixel—simultaneously accurate in meaning and crisp along boundaries—and how do we evaluate it fairly even on tiny classes?**

## Theory

### Problem formulation

An input image is $\mathbf{X} \in \mathbb{R}^{H \times W \times C}$ as before, and there are $K$ classes (including background). The ground truth is an integer **mask** $\mathbf{M}$ of size $H \times W$, where each entry $M_{ij} \in \{0, 1, \dots, K-1\}$ is the true class of the pixel at row $i$, column $j$.

The network outputs a 3D tensor of scores $\mathbf{S} \in \mathbb{R}^{H \times W \times K}$: every pixel gets $K$ logits, one per class. Applying softmax **independently at each pixel** along the channel axis converts those $K$ logits into class probabilities:

$$
p_{ijk} = \frac{e^{S_{ijk}}}{\sum_{c=0}^{K-1} e^{S_{ijc}}}
$$

The predicted class at pixel $(i, j)$ is the class with the highest probability: $\hat{y}_{ij} = \arg\max_k p_{ijk}$.

Compared to whole-image classification, only one thing has changed: instead of **one** $K$-dimensional logit vector for the entire image, we produce $H \cdot W$ such vectors. Every pixel is its own miniature classification problem.

### Loss function: per-pixel cross-entropy

Because every pixel is a classification problem, we compute the cross-entropy loss at each pixel and average over the entire image:

$$
\mathcal{L} = -\frac{1}{HW} \sum_{i=1}^{H} \sum_{j=1}^{W} \ln p_{i j M_{ij}}
$$

Reading from the inside out: $p_{ijM_{ij}}$ is the probability the network assigns to the **true class** $M_{ij}$ at pixel $(i, j)$. Taking $-\ln$ yields a loss near 0 when that probability is close to 1, and a huge penalty when it is close to 0. Dividing by $HW$ makes the loss scale-invariant with respect to image resolution. On a mini-batch of images, PyTorch's `F.cross_entropy` averages over all pixels of all images in the batch (the original FCN paper summed instead of averaging, which differs only by a constant factor).

This formula has an immediate consequence: **classes with many pixels dominate the sum**. If 80% of an image is background, a network can drive the loss down dramatically just by getting background pixels right. UNet addresses this by multiplying each pixel's loss by a spatial weight $w_{ij}$ that is much larger on rare classes and along the thin border separating touching cells.

### Evaluation metrics: pixel accuracy, IoU, and mIoU

The simplest metric is **pixel accuracy**: the fraction of pixels predicted correctly.

$$
\text{acc} = \frac{\text{number of pixels with } \hat{y}_{ij} = M_{ij}}{HW}
$$

It suffers from the exact same flaw as unweighted pixel loss. In the NumPy code cell below, a $64 \times 64$ synthetic image has 3,323 background pixels, 709 circle pixels, and just 64 pixels belonging to a small square. A model that **completely misses the square** still achieves a pixel accuracy of $4,032 / 4,096 \approx 0.984$.

**IoU** fixes this by evaluating **each class separately**. Let $A_k$ be the set of pixels predicted as class $k$, and $B_k$ be the set of pixels whose true class is $k$:

$$
\text{IoU}_k = \frac{|A_k \cap B_k|}{|A_k \cup B_k|} = \frac{\text{TP}_k}{\text{TP}_k + \text{FP}_k + \text{FN}_k}
$$

The numerator is the intersection: pixels rightly predicted as $k$ (true positives, TP). The denominator is the union, which decomposes into three disjoint sets: true positives ($\text{TP}_k$), pixels falsely predicted as $k$ (false positives, $\text{FP}_k$), and true class-$k$ pixels missed by the model (false negatives, $\text{FN}_k$). IoU equals 1 when the predicted and true regions match perfectly, and 0 when they do not overlap at all. It penalizes **both** over-prediction and under-prediction.

For the model that misses the small square: the square class has $\text{TP} = 0$, so $\text{IoU} = 0$. The background class has $\text{TP} = 3,323$, and the 64 square pixels misclassified as background count as false positives for background, giving $\text{IoU}_\text{bg} = 3,323 / 3,387 \approx 0.981$.

**mIoU** (mean IoU) is the unweighted average of $\text{IoU}_k$ across all $K$ classes, giving **every class equal weight** regardless of how many pixels it occupies:

$$
\text{mIoU} = \frac{1}{K} \sum_{k=0}^{K-1} \text{IoU}_k
$$

Now the model that missed the square gets $\text{mIoU} = (0.981 + 1 + 0)/3 \approx 0.660$—a sharp drop from 0.984. That is why mIoU is the primary benchmark metric in semantic segmentation (FCN calls it "mean IU"). Across a multi-image test set, the standard protocol is to **accumulate** total TP, FP, and FN over all test images before dividing, as our PyTorch code cell does.

:::note[Key takeaway]
Every pixel is a classification problem: $K$ logits, per-pixel softmax, and cross-entropy averaged over all pixels. Always evaluate with per-class IoU and mIoU rather than pixel accuracy alone, because tiny classes barely move pixel accuracy even when completely missed.
:::

### FCN: turning a classifier into a fully convolutional network

FCN (Long, Shelhamer, and Darrell, 2015) launched modern deep semantic segmentation with three ideas:

**Idea 1: replace fully connected layers with convolutions.** A fully connected layer that takes a $7 \times 7 \times 512$ feature map is mathematically identical to a convolutional layer whose kernel size is $7 \times 7$. Rewritten as a convolution, the network no longer requires a fixed input image size. Feed in a larger image, and instead of a single logit vector you get a spatial **grid** of logit vectors—one prediction per region. Because every layer is now convolutional, the architecture is called a **fully convolutional network**. Finally, a $1 \times 1$ convolution projects the channel dimension to $K$ classes (21 for PASCAL VOC: 20 object classes plus background).

**Idea 2: in-network upsampling.** Because a VGG-16 backbone shrinks spatial dimensions by a factor of 32 along each side—a ratio called the **output stride**—its coarse score grid must be upsampled 32x back to the original resolution. FCN uses a transposed convolution initialized to bilinear interpolation (explained next). This baseline is called FCN-32s, and its predicted object boundaries are noticeably blobby.

**Idea 3: skip connections from shallower pools.** FCN-16s takes the feature map from `pool4` (output stride 16), passes it through a $1 \times 1$ convolution to get $K$ score channels, and **adds** it element-wise to the 2x-upsampled scores from the final layer before upsampling the sum by 16x. FCN-8s repeats the trick one stage earlier with `pool3` (output stride 8). Deep layers supply "what," while shallow layers refine "where."

### Upsampling: bilinear interpolation and transposed convolution

There are three standard ways to enlarge a coarse $h \times w$ feature grid to $sh \times sw$:

- **Nearest-neighbor interpolation:** each coarse cell is simply copied into an $s \times s$ block. Fast, but produces blocky, stair-stepped boundaries.
- **Bilinear interpolation:** each new pixel is a weighted average of the 4 nearest coarse cells, with weights proportional to proximity—interpolating linearly along rows first and then along columns. Boundaries are much smoother, and there are zero learnable parameters.
- **Transposed convolution** (sometimes called "deconvolution"): each input value multiplies a **learnable** $k \times k$ kernel and "stamps" that weighted kernel onto the output grid at intervals of $s$ pixels, summing wherever stamps overlap. In PyTorch (with `output_padding=0`), the output size is $(h - 1)s - 2p + k$. Choosing $k = s = 2$ and $p = 0$ gives $(h-1) \cdot 2 + 2 = 2h$—an exact 2x upsampling with non-overlapping stamps, as used in UNet and our PyTorch script.

Transposed convolution has a well-known pitfall analyzed by Odena, Dumoulin, and Olah (2016): **checkerboard artifacts**. When the kernel size $k$ is not divisible by the stride $s$ (for example, $k = 3, s = 2$), adjacent stamps overlap **unevenly**: along each axis, every other output pixel sums contributions from two input cells while its neighbors receive input from only one. In 2D this uneven overlap forms a checkerboard grid, and stacking multiple such layers amplifies the pattern. Their recommended fix: **upsample first** using deterministic interpolation (nearest-neighbor or bilinear), then apply a standard $3 \times 3$ convolution. Choosing $k$ divisible by $s$ helps, though learned weights can still drift into uneven patterns.

### UNet: a symmetric U-shaped encoder-decoder

UNet (Ronneberger, Fischer, and Brox, 2015) was designed for biomedical microscopy, where training sets often contain only a few dozen labeled images and boundaries between touching cells are just a couple of pixels wide. Its architecture has two symmetric halves:

- **Contracting path (encoder):** repeatedly applies "two $3 \times 3$ convolutions + ReLU, followed by $2 \times 2$ max pooling." Every time spatial resolution is halved, the number of channels doubles: 64, 128, 256, 512, 1024.
- **Expansive path (decoder):** repeatedly applies "2x upsampling via $2 \times 2$ transposed convolution (halving the channels), **channel concatenation** with the matching feature map from the contracting path, and two $3 \times 3$ convolutions." A final $1 \times 1$ convolution maps the features to $K$ class logits.

Two design choices distinguish UNet from FCN: **symmetry** and **concatenation**. FCN has a paper-thin decoder that only sums $K$-channel score maps. UNet has a full multi-layer decoder whose channel capacity mirrors the encoder, and at every scale it **concatenates** the full multi-channel feature maps from the encoder rather than collapsing them to $K$ channels first. These **skip connections** shuttle fine spatial details straight across the U from encoder to decoder, bypassing the $8 \times 8$ bottleneck at the bottom.

The original UNet paper used **unpadded** convolutions, shrinking the feature map by 2 pixels at every layer (a $572 \times 572$ input produced a $388 \times 388$ output mask, requiring encoder features to be center-cropped before concatenation). Modern implementations almost universally use `padding=1` so spatial dimensions match cleanly at every level, just like our PyTorch code cell.

### FPN: feature pyramid networks

FPN (Lin et al., 2017) was originally created for object detection across multiple scales, and consists of three pathways:

1. **Bottom-up pathway:** a standard CNN backbone producing feature maps at output strides 4, 8, 16, and 32.
2. **Top-down pathway:** starting from the coarsest, deepest map, progressively upsamples features by 2x using nearest-neighbor interpolation.
3. **Lateral connections:** the backbone map at the matching resolution passes through a $1 \times 1$ convolution to set its channel count to a fixed $d = 256$, and is **added** element-wise to the upsampled map. A $3 \times 3$ convolution then smooths the sum to reduce aliasing from upsampling.

The result is a **feature pyramid** in which every level has both high semantic richness and its own spatial resolution. Panoptic FPN (Kirillov et al., 2019) attaches a lightweight semantic segmentation head on top of this pyramid. Compared to UNet, FPN uses **element-wise addition** with a fixed 256-channel width, making it much lighter in memory and compute than concatenating 512+ channels.

### DeepLab: downsample less, dilate the kernel instead

The DeepLab family (Chen et al.) takes a fundamentally different route: instead of downsampling by 32x and trying to recover lost detail later, **stop downsampling so aggressively in the first place**. Removing the stride from the last one or two stages keeps the backbone at output stride 16 or 8. However, removing stride means subsequent $3 \times 3$ kernels cover a smaller physical region of the image. How can a $3 \times 3$ kernel keep a wide receptive field without adding parameters or pooling?

**Dilated convolution** (also called **atrous convolution**, from the French *à trous* meaning "with holes") is the answer. Written in 1D for clarity, following DeepLabv3 (2017):

$$
y[i] = \sum_{t} x[i + r \cdot t]\, w[t]
$$

Here $w[t]$ is the $t$-th kernel weight, and the **dilation rate** $r$ is the stride between sampled input locations. Setting $r = 1$ recovers a standard convolution; setting $r = 2$ inserts one skipped cell between adjacent weights.

**Effective kernel size.** A kernel of size $k$ has $k - 1$ gaps between adjacent weights, and each gap skips $r - 1$ cells. The total span covered by the kernel is therefore:

$$
k_\text{eff} = k + (k - 1)(r - 1)
$$

For $k = 3$: $r = 2$ gives $k_\text{eff} = 5$, $r = 6$ gives 13, and $r = 18$ gives 37—all while keeping just $3 \times 3 = 9$ learnable weights.

**Cumulative receptive field.** For stacked stride-1 layers, each layer $\ell$ expands the receptive field by $k_{\text{eff},\ell} - 1$ pixels along each dimension. Starting from 1 pixel:

$$
R = 1 + \sum_{\ell} (k_{\text{eff},\ell} - 1)
$$

Three standard $3 \times 3$ layers give $R = 1 + 2 + 2 + 2 = 7$. Three $3 \times 3$ layers with dilation rates $r = 1, 2, 4$ give $R = 1 + 2 + 4 + 8 = 15$ with the exact same number of parameters. The receptive field grows exponentially rather than linearly, without losing spatial resolution.

**ASPP.** Because objects appear at many scales, a single dilation rate is not enough. **ASPP** (Atrous Spatial Pyramid Pooling) runs multiple branches **in parallel** on the top feature map and concatenates their outputs. In DeepLabv3 at output stride 16, ASPP combines one $1 \times 1$ convolution, three $3 \times 3$ convolutions with dilation rates 6, 12, and 18, and an **image-level feature** branch (global average pooling followed by a $1 \times 1$ conv and bilinear upsampling). The global branch has a specific motivation: when the dilation rate approaches the size of the feature map, the 8 outer weights of a $3 \times 3$ kernel fall into zero-padded borders, degenerating the filter into a $1 \times 1$ convolution; global pooling restores full-image context.

DeepLabv3+ (Chen et al., 2018) adds a lightweight UNet-style decoder on top of DeepLabv3 to sharpen object boundaries, marrying the two paradigms.

### HRNet: never throw away high resolution

Every architecture above follows a "downsample first, recover later" pipeline. HRNet (*High-Resolution Network*, Wang et al., 2020) asks: why lose high-resolution representations in the first place?

HRNet maintains a high-resolution stream (at $1/4$ image resolution) **all the way from input to output**. Each stage adds a new, lower-resolution parallel stream, eventually running four streams side by side at $1/4, 1/8, 1/16$, and $1/32$ resolution with $C, 2C, 4C$, and $8C$ channels. Repeated **multi-scale fusion** modules exchange information across all streams: higher-resolution streams downsample via strided $3 \times 3$ convolutions, lower-resolution streams upsample via bilinear interpolation and $1 \times 1$ convolutions, and each stream sums all incoming signals. For semantic segmentation, HRNetV2 bilinearly upsamples all three lower-resolution streams to $1/4$ resolution and concatenates them with the high-resolution stream.

Returning to our map analogy: UNet studies the world atlas first and then works its way down to the street map; HRNet spreads all four maps out on the table at once and cross-references them continuously.

### Limitations

- **Does not separate touching instances.** Two people standing shoulder to shoulder form a single connected "person" blob. Counting and separating individual instances is covered in [Instance and Universal Segmentation](/en/cv/instance-universal-segmentation/).
- **CNN-centric architectures.** Transformer-based segmentation models (such as Mask2Former) appear in the next lesson; how Transformers process images is covered in [Image Classification with Transformers](/en/cv/vision-transformer/).
- **Pixel-level annotations are expensive.** Tracing polygonal masks takes far more human effort than tagging whole images. [Data Augmentation in CV](/en/cv/image-augmentation/) and [Self-Supervised Learning in Vision](/en/cv/self-supervised-learning/) explore how to learn effectively when labeled masks are scarce.

The table below compares all five families around a single question: how does each architecture preserve or recover spatial resolution while combining "what" with "where"?

| Criterion | FCN (2015) | UNet (2015) | FPN (2017) | DeepLab v3/v3+ (2017–2018) | HRNet (2020) |
|---|---|---|---|---|---|
| Resolution path | Downsample 32x, upsample in one or three steps | Symmetric step-by-step downsampling and upsampling | Downsample, then top-down pyramid stage by stage | Downsample only 8x or 16x | Keep $1/4$ stream throughout alongside lower streams |
| Fusing detail & context | Add $K$-channel score maps from `pool3`, `pool4` | Concatenate full encoder feature maps at each scale | $1 \times 1$ conv + element-wise addition ($d = 256$) | Dilated convs & multi-rate ASPP; v3+ adds decoder | Repeated multi-scale cross-stream fusion |
| Upsampling operator | Transposed conv (bilinearly initialized) | $2 \times 2$ transposed conv | Nearest-neighbor | Bilinear interpolation | Bilinear interpolation |
| Key strength | Simple; directly reuses classification backbones | Crisp boundaries; works well with few training images | Lightweight multi-scale features shared with detection | Large receptive field & multi-scale context | High-resolution stream stays sharp and semantically rich |
| Trade-off | Blobby object boundaries | High memory footprint at wide, high-res levels | Needs an extra head for segmentation | Heavy compute at $1/8$ resolution | Multiple parallel branches cost memory and FLOPs |

### A tiny UNet in PyTorch

The script below generates 512 training images and 128 test images of size $32 \times 32$ (seed 0). Reading the output:

- **With skip connections (`skip=True`):** reaches 0.902 mIoU on the 128 unseen test images (0.879 on circles, 0.83 on squares). After 20 epochs, our miniature UNet cleanly separates two shapes of identical intensity based purely on geometry.
- **Without skip connections (`skip=False`):** identical architecture and random seed, except the decoder receives zeros instead of encoder features. mIoU drops to 0.706, and square IoU plunges to 0.46. Because all spatial information is forced through the $8 \times 8$ bottleneck, sharp corners and boundaries blur out—confirming our theoretical motivation.
- **Pixel accuracy** barely dips from 0.987 to 0.953, once again hiding a nearly 20-point drop in mIoU.

Even with fixed seeds, numbers may differ in the second or third decimal place across machines due to multi-threaded floating-point reduction order on CPU (running with 4 threads on our test machine gave 0.908 and 0.704 mIoU). The large gap between having and omitting skip connections always holds.

## Common pitfalls

:::caution[Reporting pixel accuracy as your primary metric]
Pixel accuracy is dominated by majority background classes. In our NumPy example, a model that completely erases the square still scores 0.984 pixel accuracy. In autonomous driving scenes, pedestrians, traffic signs, and poles occupy only a few percent of pixels yet carry the highest safety stakes. Always report **per-class IoU** and mIoU by accumulating TP, FP, and FN across the entire evaluation set before dividing. If a class is absent from both ground truth and prediction ($0/0$), exclude it from the mean rather than counting it as 0 or 1.
:::

:::caution[Resizing integer label masks with bilinear interpolation]
A segmentation mask contains **discrete class IDs**, not continuous intensities. Downsampling or rotating a mask with bilinear interpolation produces fractional numbers along boundaries, and rounding does not fix it: between background (0) and square (2), interpolation invents a halo of class 1 ("circle"). Always use **nearest-neighbor interpolation** for masks (e.g., `F.interpolate(..., mode="nearest")` or `InterpolationMode.NEAREST` in torchvision). And whenever data augmentation flips, crops, or warps an input image, apply the exact same spatial transform to its mask.
:::

:::caution[Assuming upsampling alone recovers fine spatial detail]
Bilinear interpolation and transposed convolution can only redistribute information already present in the coarse grid. At output stride 8, our $8 \times 8$ square vanished under both upsampling methods. Recovering small objects and crisp edges requires feeding high-resolution features into the decoder (UNet skip connections, FPN lateral connections, DeepLabv3+ decoder) or maintaining high resolution throughout the network (HRNet).
:::

## Summary and further reading

**Key takeaways:**

- Semantic segmentation classifies every pixel: the network outputs $H \times W \times K$ logits, applies softmax per pixel, and trains with per-pixel cross-entropy averaged over the image.
- Evaluate with $\text{IoU}_k = \text{TP}_k / (\text{TP}_k + \text{FP}_k + \text{FN}_k)$ and mIoU (the unweighted mean across classes). Pixel accuracy is dominated by large background classes and hides complete failures on small objects.
- The central trade-off: deep layers know "what" but are coarse; shallow layers know "where" but lack semantics. FCN sums coarse and shallow score maps; UNet builds a symmetric decoder with full-channel skip concatenations; FPN builds a top-down pyramid with $1 \times 1$ lateral additions; DeepLab reduces downsampling and expands receptive fields via dilated convolutions ($k_\text{eff} = k + (k-1)(r-1)$) and multi-rate ASPP; HRNet maintains a high-resolution branch throughout the entire network.
- Bilinear upsampling is parameter-free; transposed convolution is learnable, but produces checkerboard artifacts when kernel size is not divisible by stride.
